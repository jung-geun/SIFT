### 1-3. 이메일 연동 (Gmail·Outlook, 선택, 사용자 명시적 동의 후 활성화)

- **수집 항목 및 권한**: 받은편지함 메시지 제목·발신자·스니펫·본문. Gmail OAuth 연결은 `gmail.modify` 권한을 요청하며, 사용자의 메일 열람·읽음 처리·휴지통 동작을 Gmail 서버에 반영할 수 있습니다. Gmail·Outlook IMAP 연결은 해당 계정의 앱 비밀번호를 사용합니다.
- **목적**: 메일의 할 일 후보 판단, 온디바이스 요약·정리 및 마감 관련 할 일 추출
- **저장 위치**: 메시지 원문·분석의 정본은 기기 내 별도 저장소에 둡니다. 전체 iCloud 저장 범위에 명시적으로 동의한 경우 같은 Apple 계정의 CloudKit 비공개 DB로 복제합니다. 자동 메일 분석은 기기에서 처리하며, 선택한 메시지의 OpenAI 요청은 아래 1-5항의 별도 동의를 적용합니다.
- **인증 정보**: OAuth 토큰과 IMAP 앱 비밀번호는 Keychain에 저장해 해당 제공자의 인증에 사용합니다. 전체 저장 동의·계정 확인 이후 iCloud 키체인으로 복원할 수 있으며, 실행 비밀의 기기별 접근 제어·백그라운드 허용과 슬롯 포인터는 새 기기로 이전하지 않습니다.
- **메일 서버 통신**: Google LLC의 Gmail REST API (`gmail.googleapis.com`) 또는 TLS IMAP (`imap.gmail.com:993`), Microsoft의 Outlook TLS IMAP (`outlook.office365.com:993`)에 연결해 메일을 조회하고 사용자가 실행한 읽음·휴지통 동작을 반영합니다.
- **HTML 메일의 외부 시각 리소스**: HTML 메일을 열면 HTTPS 이미지·스타일·글꼴을 자동으로 불러올 수 있습니다. 해당 외부 호스트는 열람 시각과 기기 IP를 기록할 수 있습니다. JavaScript, 양식, 프레임, 미디어 및 HTTP 리소스는 차단합니다.

### 1-4. 캘린더 연동 (선택, 시스템 권한 허용 후 활성화)

- **수집 항목**: 캘린더 이벤트 (EventKit, 읽기·쓰기)
- **목적**: 사용자가 직접 요청하거나 자동 등록에 별도 동의한 경우에만 적격 할 일을 선택한 시스템 캘린더에 등록하고, 캘린더 일정을 할 일로 가져오기. 자동 등록의 기본값은 꺼짐이며, 건강(`health:`) 출처는 자동 등록에서 제외합니다. 대상 계정은 기기의 시스템 캘린더 설정으로 연결하며 별도 OAuth를 추가하지 않습니다.
- **처리 위치**: 기기 내 시스템 캘린더 프레임워크(EventKit). OpenAI로 보내는 별도 캘린더 이벤트 컨텍스트는 제목을 `Busy`로 가리고 시작·종료 시각만 포함합니다. 다만 외부 캘린더에서 가져와 진행중으로 확정한 할 일은 일반 할 일 공유 동의 범위에 포함되어 제목·메모가 전송될 수 있습니다.

### 1-5. 할 일 우선순위 및 선택형 외부 분석

- 기본 AI는 Apple Intelligence입니다. 하드웨어 미지원 기기에서만 베타 기능의 로컬 언어 모델 대체를 명시적으로 허용하고 직접 설치한 모델을 사용합니다. 지원 기기의 비활성·모델 준비 중 상태를 다른 모델 사용 동의로 취급하지 않습니다. 사용 가능한 모델이 없으면 기기 내 규칙으로 처리합니다. 할 일 정렬의 명시적 외부 제공자 선택과 별개로 회의·페르소나·행동의 기본 분석은 기기 내에서 처리하며, 페르소나·행동의 GPT 재분석은 연결된 계정과 별도 활성화·공유 동의가 있어야 직접 요청할 수 있습니다.
- **App Store 국가 제한**: StoreKit이 확인한 중국 본토 스토어(`CHN`) 또는 국가 정보 미확인 상태에서는 ChatGPT/OpenAI 화면과 인증·모델 조회·연결 테스트·분석 요청을 차단합니다. 스토어 변경을 관찰하고 앱 활성화 시 다시 확인하며, 차단 전환은 진행 요청과 늦은 결과 적용을 중단합니다. 국가 정보는 메모리에서 가용성 판단에만 사용하며 고객 프로필로 저장하거나 광고·추적에 사용하지 않습니다. 언어 변경은 이 제한을 해제하지 않습니다.
- **앱 데이터의 OpenAI 분석 요청**: 제공자 활성화·공식 ChatGPT 연결·구독 사용 권한과 별도의 데이터별 동의가 모두 필요합니다. 일반 할 일 제목·메모·마감·가용 시간, 선택한 메일 제목·본문, 완료 기록에서 만든 루틴 근거 요약, 페르소나·행동 설명을 해당 동의 범위에 한해서 사용합니다. 페르소나 컨텍스트를 할 일 정렬에 포함할 때도 페르소나 동의를 확인합니다.
- **구독 연결 테스트**: 사용자가 설정에서 직접 요청하면 짧고 고정된 테스트 메시지만 OpenAI로 보내 모델 제공·응답 완료 여부를 확인합니다. 저장된 앱 데이터나 할 일·메일·루틴·페르소나 공유 동의는 사용하지 않습니다. 연결된 계정의 구독 사용 권한은 필요하지만 외부 분석 제공자가 꺼져 있어도 테스트할 수 있으며 구독 한도를 일부 소모할 수 있습니다. 실제 앱 데이터 분석의 활성화·동의를 허용하지는 않습니다.
- **모델**: 기초 요청은 `gpt-6-luna`, 이메일 중요 내용·루틴·페르소나/행동 설명의 명시적 고급 재요청은 `gpt-6.1-sol`입니다. 계정에서 사용할 수 없는 모델을 다른 모델로 자동 대체하지 않습니다.
- **계정 모델 목록**: 연결한 계정의 OAuth 토큰으로 모델 목록을 조회해 이름·모델 ID를 표시합니다. 이 조회는 추론이나 저장된 앱 데이터 전송을 하지 않으며 다른 API의 이용 권한을 보장하지 않습니다.
- **메일의 자동 경로**: 수동 활성화·설치한 Laya와 사용 가능한 Apple Intelligence 또는 기기 내 규칙을 사용합니다. 메일·회의 출처 할 일은 자동 외부 정렬에서 제외합니다. 선택한 메일의 본문 분석은 이메일 공유 동의 후 사용자가 해당 요청 버튼을 직접 누른 경우에만 수행합니다.
- **회의·캘린더 경계**: 회의 음성·전사문·화자 정보는 OpenAI에 전송하지 않습니다. 별도 캘린더 이벤트 컨텍스트의 제목·메모는 보내지 않지만, 외부 캘린더에서 가져와 확정한 할 일의 제목·메모에는 일반 할 일 공유 동의를 적용합니다.
- **응답·취소**: 공개 Responses API에 `store:false`, `stream:true`로 요청하고 완료된 응답만 검토 초안으로 반환합니다. 제공자 측 보관·데이터 이용은 OpenAI 정책에 따르며 무보존을 보장하지 않습니다. 동의 철회·제공자 해제·계정 변경·로그아웃은 관련 진행 요청을 취소하고 늦은 응답의 적용을 차단합니다. 미완료·실패 응답은 원문을 바꾸지 않습니다.

### 1-6. 사용자 동의형 오류 진단 (선택)

- **수집 항목**: 오류 발생 시각·반복 횟수, 소스 파일·줄 번호·함수, 오류 도메인·코드·유형·메시지(파일 경로와 이메일 주소 제거, 300자 제한)와 하위 오류 사슬, 오류 당시 앱 버전·빌드·운영체제 버전·빌드·앱 실행 상태·기능 설정·언어·기기 언어 설정에서 파생한 국가/지역·시간대·UTC 오프셋·달력·24시간 설정, 보고서 준비 시점의 기기 모델 식별자·메모리·저장 공간·화면 크기·프로세서 수·언어·지역·시간대, 앱이 남긴 최근 오류 로그(최대 300건, 30분), Apple이 나중에 제공할 수 있는 충돌·멈춤·메모리 종료 진단. 국가/지역은 실제 위치가 아닌 기기 언어 설정에서 파생합니다.
- **제외 항목**: 실제 위치·GPS 위치, 기기 이름, 음성 녹음, 전사문, 할 일, 이메일 본문·제목·주소, 페르소나, 계정 식별자, 인증 토큰
- **동의 및 저장**: 사용자가 앱 내에서 명시적으로 허용한 경우에만 기기 로컬의 백업 제외·파일 보호 저장소에 제한된 개수로 보관합니다. 동의를 철회하거나 로컬 진단 로그를 삭제하면 즉시 삭제합니다.
- **전송 및 사전 검토**: 앱은 진단 로그를 자동으로 네트워크 전송하지 않습니다. 기기 로컬의 검토 화면에서 준비된 보고서 전체 원문과 실제 디스크 용량·시스템 가동 시간·부팅 시각·각 오류 시점의 스냅샷을 표시합니다. 앱 내 의견 보내기를 지원하는 버전에서는 사용자가 오류 보고에 이 보고서를 포함하고 최종 전송을 명시적으로 승인한 경우에만 같은 보고서를 HTTPS로 SIFT 비공개 접수함에 보냅니다. 메일 앱 설정이나 서비스 계정 로그인은 필요하지 않습니다. 서버의 접수가 확인된 뒤에만 해당 로컬 진단을 처리 완료로 표시합니다. 검토 취소·전송 실패 시 로컬 진단은 유지합니다. 이전 버전의 메일·공유 시트 전송은 사용자가 선택한 수신자에게 전달되며 자동 접수가 아닙니다.
- **Apple 시스템 진단**: MetricKit/App Store Connect 진단은 Apple과 기기 설정에 따라 지연되어 제공되거나 제공되지 않을 수 있으며, 모든 강제 종료를 포착하지 않습니다.

#### 앱 내 오류 보고·기능 제안

- **전송 항목과 목적**: 사용자가 직접 적은 유형·제목·설명, 앱 버전·빌드·플랫폼·OS 버전·선택 언어, 중복 접수 방지용 무작위 제출 ID를 오류 조사·기능 개선에 사용합니다. 오류 보고에 별도로 포함을 선택한 경우에만 위의 준비된 진단 보고서를 첨부합니다. 기능 제안에는 진단을 첨부하지 않습니다.
- **사용자 선택**: 입력 내용과 첨부 정보를 검토한 뒤 직접 전송할 때만 업로드합니다. 계정·이메일 연결이나 연락처 입력을 요구하지 않으며, 저장된 할 일·메일·음성·건강 기록·인증 정보를 자동 첨부하지 않습니다. 자유 입력란에 개인정보·비밀번호·메일 원문을 쓰지 마세요.
- **처리와 접근**: Cloudflare Workers가 요청을 처리하고 D1의 비공개 접수함에 저장합니다. 운영자만 인증 후 열람·분류·삭제할 수 있으며 공개 GitHub 이슈로 게시하지 않습니다. 접수번호는 접수 확인용이며 공개 조회 기능이나 개별 답변을 제공하지 않습니다.
- **보관**: 접수 내용·첨부 진단·운영 메모는 접수 후 30일이 지나면 조회 대상에서 제외하고 일일 정기 작업으로 삭제합니다. 정상 운영에서는 만료 후 다음 정기 작업까지 최대 24시간 차이가 날 수 있으며, 제공자 장애 시 삭제가 더 늦어질 수 있습니다. 운영자는 그전에 삭제할 수 있습니다. D1 무료 플랜의 시점 복구 이력에는 삭제 전 데이터가 최대 7일 남을 수 있으며 운영 접수함에서 공개 조회되지 않습니다. 로컬 로그 삭제·앱 삭제가 이미 전송한 접수 내용을 즉시 삭제하지는 않습니다. 삭제 요청에는 접수번호를 알려주세요.
- **남용 방지 및 네트워크 정보**: Cloudflare는 전송 처리 과정에서 IP 주소 등 네트워크 정보를 처리합니다. SIFT 접수 데이터에는 원본 IP나 영구 기기 식별자를 저장하지 않습니다. 일별 비밀키 기반 HMAC으로 만든 네트워크 제한 키만 최대 2일간 보관하며, 접수 본문·진단·관리자 비밀키를 애플리케이션 로그에 기록하지 않습니다. 로그인 불필요가 네트워크 제공자에게도 완전 익명임을 뜻하지는 않습니다.
- **서비스 한도**: 무료 서비스 한도·일별 접수량·본문 크기·저장량 제한에 도달하거나 네트워크가 끊기면 전송이 실패할 수 있습니다. 앱은 서버 접수 확인 없이 성공으로 표시하지 않으며, 작성 화면을 유지해 사용자가 다시 시도할 수 있게 합니다.

### 1-7. 회의 녹음·앱 오디오·화자 구분·오프라인 재전사 (선택)

- **처리 항목·플랫폼 경계**: 선택한 마이크 음성, 시스템 공유 picker로 승인한 앱/화면 출력(상대방 발화나 다른 앱 소리 포함 가능), 소스별 전사문·화자 시간 구간·사용자 이름/배정·on/off·선택 경계를 처리합니다. Mac Catalyst 경로는 최대 4개의 각각 승인한 대상과 별도 마이크, iOS 27 iPhone 경로는 단일 전체 화면 선택과 마이크입니다. iPhone은 개별 앱·사람을 선택하지 못하며 iOS 26.x와 simulator에서는 앱 오디오가 불가합니다. 이 경로 설명은 실제 회의 앱/기기의 통화 수집 검증을 뜻하지 않습니다. 화면 **영상·사진은 저장하지 않습니다**. 제3자 대화의 녹음 동의와 현지 규칙을 확인하세요. 제공자 직접 수신기는 구현하지 않았으며 제공자 API의 조건·플랫폼 경계는 별도입니다.
- **독립 소스 제어**: 마이크·승인 대상의 녹음 여부를 각각 제어하며 앱이 다른 회의 앱의 송신 음소거·청취 장치·볼륨을 바꾸지는 않습니다. 소스는 unity gain의 개별 FLAC으로 저장하며 부모에 혼합 파일이나 합친 전사문을 저장하지 않습니다. 전체 재생과 교차 대화 타임라인은 저장된 소스를 공통 시각에 맞춰 기기 안에서 읽기 전용으로 합성하며 원본을 교체하거나 추가 서버로 전송하지 않습니다. 마이크에 스피커 소리가 다시 들어오는 현상은 제거하지 못하므로 헤드폰을 권장합니다. 한 트랙의 실패는 다른 트랙의 원음·전사에 영향을 주지 않도록 분리하며 특정 앱의 실제 통화 오디오 수집은 보장하지 않습니다.
- **모델 설치·처리**: 설정 → 회의에서 직접 설치를 눌렀을 때만 Hugging Face의 고정 공개 파일을 내려받아 크기·SHA-256을 확인합니다. 화자 구분의 기본 구현은 Nemotron이며 사용 여부를 별도로 선택합니다. 사용 설정이 켜져 있어도 모델을 자동 설치하지 않으며 끄기 선택은 보존합니다. Whisper는 녹음 종료 후 선택형 베타 재전사에만 사용하고 추가 전력·시간이 필요할 수 있습니다. 자동 언어 모드도 녹음 중에는 원음만 저장하고 종료 후 언어를 감지·전사합니다. 설치 요청에 회의 음성·전사문·화자 정보를 포함하지 않습니다. Nemotron 라이브/최종 화자 분석과 WhisperKit 저장 음성 재전사는 기기에서 처리합니다. pyannote Community-1 기반 FBank/WeSpeaker는 트랙 내부 ID 연결을 위한 보조 추출기이며 Nemotron을 대체하지 않습니다. [CC BY 4.0 범위·pyannote/WeSpeaker/FluidInference 귀속](https://huggingface.co/FluidInference/speaker-diarization-coreml/blob/df2625ac79a7ac6b65ad868fee6d80f320da4232/NOTICE.md)을 유지합니다. 임베딩은 트랙별 분석 중 메모리에만 두며 저장·동기화하거나 트랙/회의 사이의 사람을 연결하지 않습니다. 불변 가중치만 공유하고 가변 모델/상태는 worker별로 분리하며 모든 라이브 트랙이 끝난 뒤 최종 패스를 순차 처리합니다.
- **원문·저장·복구**: 새 녹음은 부모와 고유 ID의 소스별 자식 기록으로 로컬에 저장합니다. 자식별 16 kHz mono FLAC·manifest, Apple 원문, 오프라인/검수 전사, Nemotron 라이브/최종 화자 ID·이름/배정, 소스 상태·선택 정보와 부모 시작 오프셋을 유지합니다. 트랙 시간은 소스 시작 0 기준입니다. 활성/종료 저널은 중단 시 읽을 수 있는 연속 음성 prefix를 복구하며 잃은 음성·전사를 만들어 채우지 않습니다. 기존 완료 기록은 독립 기록으로 남습니다. 트랙별 재생·편집·재처리·내보내기와 전체 원본 ZIP(`meeting.json`, `tracks/<child>/audio/`의 FLAC·`manifest.json`)은 사용자 선택으로 실행하며 외부 공유 시 선택한 수신자에게 음성·소스 정보가 전달될 수 있습니다. 전체 iCloud 저장 동의 후에는 회의 기록·원음·복구 정보도 같은 Apple 계정으로 복제합니다. Firebase 스냅샷에서는 제외하며 재전사·화자 분석을 위해 외부 AI 서비스로 보내지 않습니다. 원문·음성 샘플은 진단 로그에 기록하지 않습니다.
- **로컬 파일 가져오기**: 사용자가 시스템 파일 선택창에서 고른 오디오를 읽기 전용으로 열어 기기 내 회의 음성으로 변환·저장합니다. 원본 파일과 원본 위치는 바꾸지 않으며 기록에는 파일의 기본 이름만 보관합니다. 가져오기 자체는 마이크 권한·모델 다운로드·서버 업로드를 요청하지 않습니다. 파일 제공자가 원본을 다운로드하는 경우에는 해당 제공자의 정책이 적용됩니다. 모델 미설치나 전사 실패 후에도 로컬 음성은 재시도를 위해 보존되며 회의 삭제 시 앱 안의 복사본을 삭제합니다.

### 1-8. 완료 기록 기반 루틴·일정 제안 (선택)

- 기기 내 학습을 켜고 직접 분석할 때 최근 90일의 완료된 수동 할 일을 동일한 정규화 제목으로 묶습니다. 최소 3일의 완료 근거가 필요하며 메일·회의·외부 캘린더·등록 대기·삭제 항목은 제외합니다.
- 완료 체크 기록은 실제 활동 수행 시각·기간·복약·건강 상태를 입증하지 않습니다. 근거 수·기간·주기·선호 시간·불확실성을 표시하고 사용자가 확인·수정한 루틴에서만 할 일을 제안합니다.
- 수락·거절·미루기, 기존 항목과의 중복 검사, 승인 일정과 할 일 ID를 보호된 로컬 파일에 기록합니다. 가용 시간·실제 마감·앱 일정·권한 있는 캘린더 충돌을 검사하며 사용자가 구간을 승인한 뒤에만 시작일·마감일을 저장합니다. 새 알림·캘린더 내보내기는 별도 선택입니다.
- 학습을 끄면 학습·제안이 중단되고 모두 삭제하면 루틴·근거·피드백이 삭제됩니다. 이미 승인한 할 일은 별도로 삭제해야 합니다.

### 1-9. ChatGPT 연결 정보 (선택)

- 공식 SIWC 공용 클라이언트 흐름으로 계정 식별·등록 ID·기기별 host ID·부여된 범위·만료 시각·OAuth 토큰을 관리합니다. 전체 iCloud 저장 범위에 동의하고 현재 Apple 계정을 확인한 경우 등록과 토큰을 iCloud 키체인으로 동기화해 같은 계정의 다른 전체 저장 설치에서 복원합니다. 기존 기기 전용 연결도 이 정책에 맞춰 복제하며 host ID는 수신 기기의 고유 값을 유지합니다. iCloud 비활성·로컬 전용 빌드는 클라우드 연결을 가져오거나 올리지 않습니다. 제공자 활성화·데이터 전송 동의는 각 기기에서 별도로 설정합니다.
- 로그아웃은 토큰을 지우고 원격 철회를 시도하되 재연결용 등록을 남깁니다. 연결 기록 모두 삭제는 등록·host ID·자격증명을 삭제합니다. 네트워크 실패 시 원격 철회 완료를 보장하지 않으며 ChatGPT 설정에서 앱 권한을 관리할 수 있습니다.
- iCloud 키체인의 실제 전파 시점은 Apple이 결정합니다. 앱 활성화와 요청 전 연결을 다시 읽지만 즉시 전파·오프라인 복원을 보장하지 않습니다. 회전 토큰의 갱신 소유권 표시는 자격증명과 함께 동기화하며, 갱신은 연결을 승인한 설치 한 곳에서만 실행합니다. 다른 기기는 만료 전 토큰을 사용할 수 있고, 만료 후에는 원래 기기에서 SIFT를 열어 갱신·동기화를 기다리거나 현재 기기에서 명시적으로 다시 연결해야 합니다. 실패한 토큰의 기기별 격리는 로그아웃·공유 삭제와 구분하며 늦게 도착한 유효 토큰은 수용합니다. 명시적으로 공유 세션을 원격 철회하면 다른 기기의 같은 연결에도 영향을 줄 수 있습니다.
- 로컬 로그인이 저장된 뒤 전파가 중단되면 비밀 원문이 아닌 게시 대기·기준 해시를 기기에 기록합니다. 다른 기기의 변경과 충돌하면 로컬·공유 버전을 모두 보존하고 동기화 상태로 알리며 로컬 로그인을 자동으로 이전 값으로 되돌리지 않습니다. 이 운영 메타데이터는 다른 기기의 설정으로 복원하지 않습니다.
- [공식 적용 범위](https://developers.openai.com/siwc/token-sharing-open-source)는 공개 소스·로컬 호스트 앱이며 유료·원격 호스트 배포에는 별도 OpenAI 승인이 필요합니다. 플랜·계정·모델별 권한과 사용 한도가 적용됩니다.

### 1-10. 실제 건강·운동 기록 연결 (선택)

- **범위·권한**: 사용자가 설정에서 명시적으로 연결한 항목에 한해 HealthKit의 최근 최대 90일 운동 또는 복약 기록을 읽습니다. 각 항목은 독립적으로 연결하며 쓰기·임상 기록·백그라운드 전달 권한은 요청하지 않습니다. 복약은 iOS 26 이상의 실제 복용(`taken`) 이벤트와 사용자 표시용 약 이름을 사용하며 용량·단위·처방 일정·복약 순응도를 수집하거나 추론하지 않습니다. Mac Catalyst에서는 건강 기록 읽기를 지원하지 않아 연결을 비활성화합니다. 권한 요청 완료는 읽기 허용의 증거가 아니며 빈 결과로 거부 여부를 판별하지 않습니다.
- **로컬 처리·승인**: 출처 앱은 기본적으로 미승인입니다. 승인한 출처의 최소 4일 기록과 80% 이상의 주기·시간 일관성을 근거로 후보를 만들고, 사용자가 제목·주기·시간·기준 날짜·시간대를 검토·확정해야 활성화합니다. 여러 약이나 출처를 합치지 않으며 하루 여러 번의 복약을 하루 한 번 처방으로 해석하지 않습니다. 의료 조언·처방/용량 변경·복용 누락/보충 조언은 제공하지 않습니다.
- **저장**: 원본 기록의 제한된 투영·출처 승인·후보·생성 동의·중복 방지 표식은 파일 보호와 백업 제외를 적용한 기기 전용 저장소에 보관하며 CloudKit·Firebase·OpenAI로 전송하지 않습니다. 생성한 건강 출처 할 일도 자동 OpenAI 분석, 일반 행동/페르소나 근거, 완료 체크 학습, 자동 캘린더 등록과 자동 알림 배정에서 제외합니다.
- **할 일 생성과 동기화**: 출처 승인·루틴 확정 외에 별도의 자동 생성 동의가 필요합니다. 생성한 할 일의 제목·일정도 건강 정보를 드러낼 수 있으므로 [Apple 정책](https://developer.apple.com/app-store/review/guidelines/#health-and-health-research)에 따라 iCloud 전체 저장에서 제외합니다. 사용자가 직접 실행하는 암호화 Firebase 스냅샷에는 포함되며, 이 경계를 생성 동의 전에 고지합니다. 다음 미래 발생분만 만들고 과거 일정을 소급 생성하지 않습니다. 개별 할 일에서 직접 선택한 캘린더 내보내기·알림은 별개의 사용자 동작입니다.
- **중단·삭제**: 연결 해제는 해당 항목의 읽기·로컬 근거·출처 승인을 중단/삭제합니다. 기록 지우기는 모든 연결·생성 동의·원본·후보를 지우지만 기존 할 일과 비임상 중복 방지 표식은 유지합니다. 전체 초기화만 표식을 지우며 기존 할 일이 남아 다시 생성될 수 있음을 확인합니다. 앱에서 HealthKit 원본을 수정하거나 OS 읽기 권한을 철회하지 않습니다.


### 1-11. Google AdMob 광고 및 동의 관리 (광고 제공 버전에 한함)

- **적용 범위·광고 설정**: 아래 내용은 광고를 제공하는 iOS·iPadOS 버전에서 광고 기능을 실제 제공하는 경우에 적용되며, 광고 기능이 없는 기존 배포 버전이나 Mac 앱에서 이 처리가 이루어진다는 뜻은 아닙니다. Google Mobile Ads SDK(AdMob)에 비개인화 광고를 요청합니다. ATT(앱 추적 투명성) 팝업을 표시하거나 IDFA(광고 식별자) 접근 권한을 요청하지 않으며, 게시자 퍼스트 파티 ID(publisher first-party ID)는 비활성화합니다.
- **동의 및 광고 요청**: 광고 요청 전에 Google UMP(User Messaging Platform)로 동의 상태를 확인·갱신하고 필요한 동의 화면을 표시합니다. UMP의 동의 상태가 광고 요청을 허용하는 경우에만 광고를 요청하며, 개인정보 보호 옵션 제공이 필요한 경우 앱 설정에서 해당 화면을 다시 열어 선택을 변경할 수 있습니다. 비개인화 요청은 이 동의 절차를 대체하지 않습니다.
- **SDK가 처리할 수 있는 정보·목적**: Google의 [iOS SDK 데이터 공개 안내](https://developers.google.com/admob/ios/privacy/data-disclosure)에 따라 IP 주소와 이로부터 추정한 대략적 위치, 앱·기기 식별자, 광고 노출·조회·클릭 등 상호작용, 충돌 로그 및 앱 실행 시간·멈춤·에너지 사용량 등 진단·성능 정보를 처리할 수 있습니다. IDFA 권한을 요청하지 않고 게시자 퍼스트 파티 ID를 꺼도 다른 앱·개발자 범위의 기기 식별자나 네트워크 정보 처리가 모두 없어지는 것은 아닙니다. SDK의 개인정보 보호 선언에는 사용자와 연결되거나 추적에 사용될 수 있는 데이터가 포함되므로 비개인화 요청·ATT 미요청이 모든 추적을 배제한다는 뜻도 아닙니다. 이 정보는 광고 제공, 부정행위·남용 방지, 광고 효과 측정·분석 및 SDK 성능 개선에 사용될 수 있습니다.
- **앱 콘텐츠·건강정보 경계**: 할 일·이메일·캘린더·건강 기록·음성/전사문·페르소나의 내용을 광고 타기팅용으로 전송하지 않습니다. HealthKit 데이터와 그로부터 생성한 건강 출처 할 일 등 파생 정보는 광고에 사용하지 않으며 광고 SDK나 UMP로 전달하지 않습니다. Gmail 데이터의 광고·제3자 마케팅 이용 금지는 아래 4항과 같이 유지합니다.
- **SIFT 오류 진단과의 구분**: 광고 SDK의 자동 진단·성능 정보 처리는 1-6항의 선택형 SIFT 오류 보고·로컬 진단 로그와 별개입니다. SIFT 오류 진단 동의를 끄거나 보고서를 보내지 않아도, 광고 관련 동의 상태와 Google 정책에 따라 SDK 자체의 진단·성능 정보가 처리될 수 있습니다.
- **처리·보관 및 관련 정책**: 비개인화 광고가 완전 익명이나 데이터 무수집·무보관을 뜻하지 않습니다. 실제 처리 범위는 UMP에서의 선택·적용되는 동의 상태 및 Google 정책에 따르며, Google 측 보관·삭제 기준은 [Google 개인정보처리방침](https://policies.google.com/privacy)과 [Google 서비스를 사용하는 사이트·앱의 정보 이용 안내](https://policies.google.com/technologies/partner-sites)를 확인하세요. 광고 동의 변경이나 앱의 로컬 데이터 삭제만으로 Google이 이미 처리한 정보가 즉시 삭제되는 것은 아닙니다.
